# frog makes really good PRs and signs them

Spec, written 2026-10-24. Status: proposed. Beat 1–2 sized.

Every frog PR on GitHub is a live demo the owner chose to ship: real code, in a real repo, that a person read and merged. So the PR itself should sell frog — a body a reviewer is glad to get (what was asked, who did what, what was checked and what wasn't) and one quiet signature line naming frog and pointing at the session replay.

This spec extends docs/design/pr-lifecycle.md ("A session owns its PR end to end", branch `frog/pr-lifecycle-spec`). That spec owns the forge tools and daemon: `OpenPR` already takes a `body` string (§2.1), the `Forge` trait and backends live in `crates/frog-engine/src/forge/` (§2.2–2.3), the daemon D delivers `PrOpened`/`CiStatusChanged`/`Merged` events (§8), and `[pr]` settings already exist in `config.rs` (§7). This spec defines what those tools render: the body, the signature, the commit trailers, and the outcome record the gym learns from. It adds no new tools.

Principles (docs/onboarding.md voice):

1. **Built from the log, not the model.** Every claim comes from a session record. The model can add notes; it can't add a green check.
2. **Honest about gaps.** "not run" is a line in the body, not an omission. Never fake green.
3. **Credit flows down.** The session — and every fork/worker behind it — is named in the body and in the commits.
4. **One line, not a card.** The signature is a single `<sub>` line. No logo, no banner, no badge.
5. **Signing in adds, never unlocks.** Body, signature and trailers work with no account; only the replay link is uploaded.

## 1. The PR body, from session data

A pure engine function, `forge::body`, builds the body from the session's log (and its `forked_from` lineage) before `OpenPR` runs. Sections in order, then the signature (§2):

```markdown
<the task: the user's ask, one paragraph>

**who**
- **<session name>** (<model>) · <one line on what it did> · <n> commits

**verified**
- `<command>` · <pass count or "ok">
  <details><summary>output</summary> … last lines … </details>

**not verified**
- <what wasn't run, or didn't hold, one line each>

<signature>
```

### 1.1 The task
- The session's first user input (`TurnStarted.input`), trimmed to ~280 characters at a sentence boundary. It is the ask as written — for a worker, the chief's brief.
- No heading; it stands alone as the opening paragraph. The PR title defaults to the session title, else the first commit subject.

### 1.2 who
The org that made the change, one bullet per contributing session, indented under its parent via `Header.forked_from` (crates/frog-engine/src/session.rs:56) and the app's parent links (Library.parents; Sidebar.swift `home(_:)` walks them):

- Name: the session title (`Event::Titled`), else the worktree/branch slug (`frog/stream-retry` → "stream retry"). Ids never appear.
- Model: the header's `model` spec, short form.
- One line: the session's last reply, first sentence, ≤100 characters; else its commit subjects.
- A human commit on the branch is credited by git author name — frog never takes credit for a person's work.

### 1.3 verified
What actually ran, with real output:

- A Bash call counts when its result shows exit 0 and the command matches a check pattern: test runners (`cargo test`, `npm test`, `swift test`, `pytest`, `go test`), linters/type checks (`cargo clippy`, `tsc`, `eslint`), builds (`cargo build`, `swift build`, `npm run build`). Repo-specific scripts can be added via config (§2).
- Only each command's last run counts, and only if it ran after the last edit it covers; otherwise it moves to "not verified".
- Pass counts parsed from the output (`test result: ok. 277 passed; 0 failed; 1 ignored; 0 measured; 11 filtered out`). Skips are reported honestly: "11 skipped (sandbox-exec/openpty denied in this sandbox)".
- Output tail (last ~6 lines, ANSI stripped via the same path as `strip_ansi` in tools/bash.rs, `$HOME` → `~`) folded in `<details>`. At most 4 commands: tests, then lint, then build.
- CI is not claimed here at open time; `CiStatusChanged` (pr-lifecycle §8) updates one `ci · …` line after open.

### 1.4 not verified
The honest half, one line each; omit only when genuinely empty, never pad:

- `not run: <check>` — a check the repo defines (workspace tests, `package.json` scripts) that the session never ran.
- `ran before the last edit: <command>`.
- `failed: <command>` — last run failed; the PR then opens as a draft.
- `skipped: <n> tests (<reason>)` — environmental skips, stated as observed in the output.
- `no tests touched` — diff changes source but no test file.
- `ci: <note>` — only from `pr.ci_note` set by a person in config; frog never guesses CI health.

### 1.5 Voice and edits
- Lowercase bold labels, no `##` headings (headings shout on a PR page), commands in backticks, no emoji, no "generated by" banner. Reads as plain text in a squash-merge commit message.
- The model may pass its own `body` to `OpenPR`; it is inserted between the task and **who**, untouched. The engine-built sections are never model-editable.
- After open, the body is updated only by the forge tools (check-state line, replay token injection) via the same content-ownership rule pr-lifecycle §5 gives the session over its PR body.

## 2. The signature

The last line of every body:

```markdown
<sub>built with [frog](https://frog.toys) · [session replay](https://frog.toys/s/<token>) · [receipts](https://frog.toys/s/<token>#receipts)</sub>
```

- `built with frog` links to frog.toys — a reviewer who liked the PR is one click from the thing that made it.
- `session replay` links to the replay page for this session's log; `#receipts` opens its receipts view (each commit with the session that made it and the checks that ran after it).
- Three levels, from config (§2.1):
  - `full`: the line above.
  - `short`: `<sub>built with [frog](https://frog.toys)</sub>` — nothing leaves the Mac beyond the PR itself.
  - `off`: no line. Trailers (§3) are still written; they're receipts, not marketing.
- Until the replay endpoint exists, `full` renders as `short` (no dead links in the wild).

### 2.1 Where the setting lives

frog reads per-project state from the repo's `.frog/` directory today: rules (`.frog/rules`, crates/frog-engine/src/rules.rs:12), skills (`.frog/skills`, docs/reference.md:88), worktrees (`.frog/worktrees/`, SessionBroker.swift creates them there), and `<project>/.mcp.json` for MCP servers (docs/reference.md:67). There is no repo-level config file; user settings live in `~/.config/frog/config.toml` (docs/reference.md:44).

The fitting home is a new committed file, **`<repo>/.frog/config.toml`**, with a `[pr]` table — the repo owner's one-time call for every frog contributor, sitting next to the rules and skills the repo already gives frog. The user's `~/.config/frog/config.toml` gets the same table as fallback, and an untracked `.frog/config.local.toml` overrides both for a session owner who isn't the repo owner.

```toml
# <repo>/.frog/config.toml
[pr]
signature = "full"          # "full" | "short" | "off"
checks = ["scripts/check"]  # extra commands that count as verified (§1.3)
ci_note = ""                # shown verbatim under "not verified" (§1.4)
```

Resolution: a repo `off` always wins; otherwise first set wins — `.frog/config.local.toml` → `.frog/config.toml` → user `config.toml` `[pr]` → default.

Defaults: **`full` on frog's own repos** (origin under the frog org's GitHub, like `ecto/frog` and `muni-works/*` — these PRs are the public dogfood and the replay is the point) and **`short` elsewhere**, with a one-time line in the app the first time `OpenPR` runs in a repo (onboarding principle 4, one line, not a card):

> Add a session replay link to PRs here? **Yes** · **Not here** · ×

Yes writes `signature = "full"` to `.frog/config.local.toml`; Not here writes `"short"` there; × asks again next PR. Only the `[pr]` table is read from the repo file; unknown tables are ignored with a warning, so a cloned repo can't change providers, keys or permission modes.

### 2.2 The replay link (coordination with zest)

The endpoint is owned by the zest share-link edge work (frog.toys/s). This spec defines the link and the payload; it doesn't design the endpoint.

- Link: `https://frog.toys/s/<token>`, `<token>` = 22-character base62 (128 random bits) minted by the share service; never the session id and never derived from it. `#receipts` and `#c<sha7>` as section anchors.
- One token per PR, covering the session and its `forked_from` lineage. Recorded as a durable `Event::ShareCreated { token }` so later body edits keep the same link.
- **Upload bundle** (built by the engine at `OpenPR` time, redacted on the Mac): the session log's `Header` (id, model, created, `forked_from`), `TurnStarted` inputs, final assistant texts, Bash calls with their commands and truncated results (2 KB each), `TurnEnded` usage, the `Checkpoint`/commit shas, and `CiStatusChanged` events for the branch. Excluded: reasoning blocks, deltas, images, compaction summaries, anything from sessions whose commits aren't on the branch.
- Redaction reuses frog's existing machinery: the secret pattern from `irc.rs` (`SECRET`, crates/frog-engine/src/irc.rs:314) → `[secret]`, `$HOME` → `~`, `.gitignore`d file contents in tool results → `[ignored file]`. First upload in a repo shows the bundle in-app for approval ("12 KB, 1 session, 2 secrets redacted. Upload.").
- Revocation without an account: the engine keeps a local delete key per token; deleting the share makes the page show "taken down by its owner" (the PR body isn't edited — frog may no longer have access).

**Asks for zest:**
1. `POST` endpoint: redacted bundle in → 22-char base62 token out, served at `frog.toys/s/<token>`.
2. A locally-held delete key returned with the token, so revoke works with no account.
3. Anonymous uploads allowed (signing in adds a list of your replays; it never unlocks the link).
4. Size limit and retention for bundles, and the takedown page state.
5. A receipts view (`#receipts`, `#c<sha7>`) rendering the commits and check records in the bundle.

## 3. Receipts

Every commit on a frog branch says who certified it and which session made it:

```
fix(engine): retry mid-stream gateway errors, not just pre-stream HTTP failures

Signed-off-by: Cam Pedersen <cam@campedersen.com>
Co-authored-by: engine retry loop <engine-retry-loop@frog.local>
```

### 3.1 DCO
- `git commit -s`, as today: CONTRIBUTING.md ("Sign off each commit to certify you wrote it") and `.github/workflows/dco.yml` already enforce a `Signed-off-by` on every non-merge commit of each PR. The sign-off is the git user's — a person. A model can't certify the DCO; the person running frog in their repo with their identity does.
- frog never writes a `Signed-off-by` naming a worker or a model.

### 3.2 Co-authored-by, from frog's session structure

One trailer per frog session that made the commit:

```
Co-authored-by: <session name> <<session-slug>@frog.local>
```

- Name: the session title ("engine retry loop"). Slug: title lowercased, non-alphanumerics → `-`. Distinct per-worker emails keep GitHub from collapsing co-authors into one; `frog.local` matches no GitHub account, so the name shows without an avatar — the name is the credit.
- Commits made by a person directly in the worktree get no trailer.
- A session that makes several commits (the example session made three checkpoints across turns, one final commit) carries the same trailer on each.

**Gap: frog doesn't record which session made which commit.** Verified today:
- `Header.forked_from { session, seq }` (crates/frog-engine/src/session.rs:56) ties a fork to its parent, and the app resolves parents through `Library.parents` / Sidebar's `home(_:)` walk — but nothing maps commits to sessions.
- No `Co-authored-by` trailer exists in frog's history (checked recent commits; only `Signed-off-by`).
- pr-lifecycle §5 gives a session content ownership of its PR body, which only weakly binds branch → session.

**Fix (two parts, minimal):**
1. **Record it.** After each Bash call, the engine diffs `git rev-parse HEAD` before/after in `ctx.cwd`; new commits become a durable record (new `Event::Committed { shas }`, or reuse the `Checkpoint` mechanism's turn pinning). `forge::body` builds §1.2 from these records; branch-name attribution is the fallback for older sessions and human commits.
2. **Write the trailer at commit time.** The Bash tool sets `FROG_SESSION_NAME`/`FROG_SESSION_SLUG` in the child environment and points git at frog's hook dir via env-scoped `GIT_CONFIG_COUNT`/`core.hooksPath` — nothing is written into the repo. frog's `prepare-commit-msg` runs the repo's own hook first (repo-configured `core.hooksPath` or `.git/hooks`), then appends the trailer with `git interpret-trailers --if-exists doNothing`; other hook names pass through untouched. Escape hatch `pr.trailers = false` disables trailers without breaking §1.2 (records still credit the body). frog never rewrites existing commits to add trailers.

### 3.3 Merges keep receipts
- pr-lifecycle's queue merges with `expect_head` and the repo's merge method; on frog's repos the squash-merge default collapses per-commit trailers into the squash message — GitHub's squash carries the squashed commits' co-author trailers, but the per-commit sign-offs become the DCO bot's pre-merge concern. Confirm behavior on a scratch repo before relying on it (§5 gaps). A rebase-style merge preserves everything.

## 4. Gym hook

A PR that merges as opened is the cleanest reward signal frog gets from the world: the repo owner read it and shipped it without asking for changes. pr-lifecycle's D already observes every transition as durable events (`CiStatusChanged`, `ReviewReceived`, `Merged`); this spec adds one derived record at terminal state, written by D into the opening session's log: `Event::PrOutcome { number, merged, rework_commits, review_rounds, ci_reruns, open_ms }` — rework commits are commits pushed after open, review rounds are `changes_requested`→push cycles, CI reruns are re-runs with no new commit. Merged with all three zero is the PR-quality reward (1.0); each rework commit, round and rerun subtracts (weights are the gym's call, not this spec's); closed-unmerged is 0; still open past 14 days is left unscored rather than counted a failure. The gym harvests these with the session that produced them, so trajectory and outcome travel together into dart 2 — and because the body sections (§1) are part of the trajectory, a body that said "not run" honestly and still merged teaches the right thing.
