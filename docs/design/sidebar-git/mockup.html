Sidebar git badges: mockup

The org tree (Today scope) with git badges, using the session names and counts from the live listing. The left window is light and the right is dark, with the same data. A badge sits left of the age and the state glyph, which keep their columns. Purple branch + N is commits ahead of origin/main. A dot on it means the tree is dirty and the session has settled. Green merge means landed in base (no number on a leaf, the count on a group). Amber means stuck mid-rebase or merge. Managers and done folds sum their children, deduped by tree. See README.md §1–§3.

Light. Hovering accounts ux spec v3 shows the tooltip. The manager rows read their whole subtree whatever the scope: frog manager ⎇ 37 = 1 + 2 + 10 + 17 + 7, and its ⇡ 12 includes the 11 in “11 earlier”.

Dark. frog cloud manager is collapsed (“· 2 running · 1 waiting”), and its aggregate stays the same (⎇ 20). okc decode layer finished with 19 files uncommitted (the dot). That dot also rides up to okc manager. kv quant sweep stopped mid-rebase (amber), so tang manager v2 turns amber too.

One index, two projections.
  1. A session row shows the summary: ⎇ 17.
  2. Clicking the badge (or “Show in Workers” in the row menu) switches the scope to Workers and expands that tree, with path, base, the sessions folded into it, and the PR line.
  3. The tree row shows the full meta (↑17 ↓133, the branch chip amber because it has diverged more than 20). It's the same numbers from the same GitIndex entry.
  4. Refresh is the only thing that touches the network: git fetch origin main, then gh pr view frog/accounts-ux-spec, cached by (tip, base) sha.
  5. The row's ⇡ and Workers' merged use one test, so “Clean up 6 merged” and a manager's ⇡ count the same trees.
