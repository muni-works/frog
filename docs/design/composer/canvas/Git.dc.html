6. The status line: git

When nothing more urgent is showing, a session with a repo uses the status line for its git state: the repo, the branch, what changed, the pull request, and one action at the right. The action is always the next sensible step, and there is only ever one. With nothing to report, the line is not there.

One action.Commit when there are changes; then Open PR; then Push, Fix, Merge, Archive or Reopen as the PR's state calls for. Merge and Archive ask first, in this same line. Green once.Open PR turns green only when the work is done in its own worktree and a PR is wanted. That is the single place the status line is ever filled. The same action is in the sidebar.The Changes tab ends with Commit and Open PR. Both places run the same step; the status line is there when the sidebar is closed. PR state is a dot and a word.Grey draft or closed, orange checking, red failing, green approved, violet merged. The word is always present, so colour is never the only signal. On the web cloud sessions show the same line. The web never urges Open PR in green: it can't tell whether the session has its own worktree. With "open a PR when done" off, Open PR is never offered.
