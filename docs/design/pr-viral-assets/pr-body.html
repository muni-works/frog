Engine robustness (crates/frog-engine/src/engine.rs, retry loop near fn retryable and its call site). A worker turn on glm-5.3 died on an in-stream gateway error: a 2xx stream that failed mid-flight. Two gaps: (1) retryable() only matches HttpError statuses and reqwest timeouts — in-stream error events aren't retried; (2) once streaming has started, no retry happens at all. Fix: classify these as retryable; discard the partial reply and re-run the step with backoff, up to 3 times. Never retry 4xx auth/validation errors.
