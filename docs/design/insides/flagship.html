1The pitchCode review is the bottleneck of agentic coding. Agents write 10× more code, and humans still read it line by line. frog turns a 400-line diff into a 4-line review, and shows its working.
2Why only frogLogprobs show that the model guessed. Grounding (which lines it read), branching at a token and routing fingerprints need the model's internals and its cache. Closed APIs don't expose them. frog owns the stack: tang on Metal, open weights.
3The flywheelEvery keep, edit or revert calibrates the risk score for that user, repo and model. The longer you use frog, the fewer lines you review. That data never leaves the machine, so it's private and it's yours.
4What it becomesA trust layer for any agent's output. Run another agent's diff through frog's model to get grounding and risk on code it didn't write. An enterprise reviewer that knows which lines to distrust.
The metric to prove before anyone writes a check: on a fixed set of seeded-bug agent diffs, reviewers using frog's queue catch as many bugs as reviewers reading every line, in less than a quarter of the time. Ship that as a public benchmark next to bench v2.
