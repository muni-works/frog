The honest bar

Bytes kept at the same RMSE 0.01 bound, as a fraction of the raw field. On float arrays with continuous structure, byte-oriented compressors barely compress — the mantissa noise defeats LZ. That gap is the product.

cram (lossy)0.935 MB zstd-33.86 MB zstd-193.86 MB xz-93.84 MB brotli-113.83 MB

KV-K, 8×1024×128 f32, 4.19 MB raw. Lossless arms compress exactly; cram reconstructs within the stated bound. That's the trade, and it's the whole point. On text or already-compressed bytes cram doesn't pretend: the container ties the best arm and adds 13 header bytes.

KV cache restore on a datacenter GPU

The compressed-KV decoder, ported to CUDA and measured on a rented H200 (60 streams per dispatch — about one cache step of values; every line bit-identical to the CPU reference decoder). The kernel is integer/branch-bound, so this is a restore-overhead number — the cost of decompressing once on a prefix-cache hit or a node handoff — not a memory-bandwidth one.

8×2048×128 f32, RMSE 0.01, bit-identical on every run. The plain-lane configs are 2.7–3.7 G val/s on the H200 — the lane-32 config is the headline and the plain one is the same breath. A consumer RTX 3090 does 2.4–2.5 on the same shapes (an M4 Max's Metal numbers: 2.12–3.20). The CUDA port matches or beats Metal per GPU class at wide lanes and loses at narrow ones. One bar's caveat, on the record: the in-loop verdict above still stands — this number is for restoring caches, not decoding inside attention.

How it works

f32 field→CDF 9/7 wavelet→integer prediction→quantize→context-mixed rANS→stream
1Predict, then pay only for surprise

A wavelet concentrates the field's energy. Per-band integer predictors and a deadzone quantizer leave small residuals; a sparse correction stream enforces the pointwise bound where it's needed. An encoder portfolio also tries Tucker, SZ-style interpolation, Lorenzo and tensor-train candidates, and keeps whichever stream is smallest.

2Learned contexts, integer arithmetic

Symbol probabilities come from hand-designed contexts or from a small integer MLP. The MLP is integer-only end to end, so every machine computes the same probabilities — the coder's output, and the decoded field, are identical down to the last bit.

3Where it belongs in inference

Storing and moving caches: weights, KV blocks, prefix-cache handoffs between nodes. The KV codec streams one token at a time (+0.6% bits), and the in-loop verdict is on record: decoding inside the attention step ran 1.8–5.5× slower than bf16, so cram is for storage and transit, decompressed once on load. Any claim that it speeds up your context window would be wrong, and we're not making it. The KV decode kernel runs on Metal and CUDA (a straight port of the same tables); on a datacenter H200 it restores a compressed cache at 2.7–8.6 billion values/s, bit-identical to the CPU decoder — a restore number (prefix-cache hit, node migration), not an in-loop one.
