# Vendored zest mock gateway

Copied from the private zest repo at `ae1c73f` (`sandbox/mock/mock-gateway.mjs`, `sandbox/container/{ws,session}.mjs`, `sandbox/container/fixtures/demo.jsonl`) so CI here can run it. Only the import paths changed, plus `Op::Submit` reading `text` (ecto/zest#79). Re-copy when zest changes the mock. Live previews (`preview.mjs`, the `/preview` route) are from zest's `claude/sandbox-preview` branch; here `npm run mock` serves `public/preview.js` as the capture script, and `GET /v1/sessions` carries `preview: true` (muni-works/zest#199; `startMock({ previews: false })` is an older gateway without it).

**Local additions (not in zest):** `account.mjs` answers the edge's account routes (`/v1/models`, `/v1/me`, `/v1/machines`, `/v1/keys`, `/v1/billing/history`, `/v1/coupons/redeem` with made-up codes) so the sidebar and Settings render against the mock; `mock-gateway.mjs` calls it before its own routes (two lines). Keep them when re-copying.

**Slow starts (local addition):** `startMock({ bootMs, bootFail, fresh, createMs, welcomeMs })`, or `--boot-ms`, `--boot-fail <reason>`, `--fresh`, `--create-ms`, `--welcome-ms` on the command line. `bootMs` boots like zest's `session.ts`: POST answers at once with state `starting`, the socket welcomes at once, a submit waits for the boot, then the state is `running` (or `error` with the `bootFail` reason, and the submit is dropped, as zest drops it when `wake()` throws). `fresh` leaves out the recorded turn, so a new session's log starts empty and its first turn is 1. `createMs` holds the POST answer; `welcomeMs` delays the welcome. Run against the app: `node test/mock/mock-gateway.mjs --port 8791 --boot-ms 9000 --fresh --create-ms 900 --welcome-ms 400`, then vite with `GATEWAY=http://127.0.0.1:8791 VITE_API=http://localhost:<vite port>` and `localStorage['frog.key']` set to any string.

**Credit wall (local, not in zest):** a played turn costs 6¢ of the account's mock credit (`qwen3-coder-next` is priced in `account.mjs` to match); a turn that can't pay stops after its tool call with `billing_limit`, or at once with nothing left. `{"op":"continue","note"}` plays like a submit. `POST /v1/billing/topup` returns `<return>/?session_id=cs_mock_…` and adds the credit 1.5 s later; `POST /v1/mock/credit {cents}` sets the balance. `--auto-allow` answers the recording's permission request at once. Keep these when re-copying.

**Plans and fresh accounts (local, not in zest):** `POST /v1/billing/subscribe {plan, return}` answers like the top-up (`<return>/?session_id=cs_mock_…`) and starts the plan 1.5 s later. `POST /v1/mock/account {credit_cents?, history?, plan?, weekly?, fiveHour?, handle?}` sets up a state: a fresh account is `{credit_cents: 25, history: []}`, a plan `{plan: "pro", weekly: 0.12}` (`plan: null` takes it away). Keep these when re-copying.
